# Product

## Register

product

## Users

GlobeTrotter is used by a final-semester ICT student, assessors, and demo users reviewing a secure distributed-systems portfolio project. Users are usually validating workflows locally: account creation, destination search, itinerary creation, and sharing access between users.

## Product Purpose

The product demonstrates a travel recommendation and itinerary system that starts as a secure monolith and can evolve into microservices, cloud deployment, and resilience patterns. Success means the app is usable end to end while clearly preserving the security model around authentication, authorization, validation, and audit logging.

## Brand Personality

Clear, trustworthy, practical. The interface should feel like a serious travel operations tool, not a decorative tourism website.

## Anti-references

Avoid generic travel landing pages, oversized scenic heroes, purple AI gradients, glass-heavy cards, and playful consumer booking-site chrome. Do not make security-sensitive actions look casual or decorative.

## Design Principles

- Security posture stays visible through clear permissions, constrained actions, and direct error states.
- Workflows beat spectacle: users should reach signup, login, search, create, edit, and share quickly.
- Interface density should support assessment and repeated testing without feeling cramped.
- Client-side hiding is only guidance; the API remains the enforcement boundary.
- Every empty state should point to the next useful action.

## Accessibility & Inclusion

Target WCAG AA contrast, visible keyboard focus, readable labels, and reduced-motion-safe transitions. Forms should use explicit labels and inline status messages.
